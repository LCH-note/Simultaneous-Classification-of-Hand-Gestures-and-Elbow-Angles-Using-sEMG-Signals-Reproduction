머신러닝 정확도 차이 원인 분석
작성일: 2026-10-19

======================================================================
1. 핵심 결론
======================================================================

현재 정확도가 논문보다 낮게 나온 가장 큰 이유는 모델 성능 자체보다
평가 단위가 논문과 다르기 때문이다.

논문은 테스트 데이터 384개 시행을 평가하지만, 현재 코드는 384개 시행에서
생성된 7,296개 윈도우(384 × 19)를 각각 독립 표본으로 평가한다.

동일 데이터와 동일 분할에서 확인한 결과는 다음과 같다.

평가 방식                     SVM       RF        XGB
윈도우별 정확도               48.41%    61.95%    60.18%
시행별 다수결                 85.68%    97.14%    94.01%
시행별 점수 또는 확률 평균    83.07%    98.96%    97.14%

RF와 XGB는 현재 데이터에도 시행을 구분할 정보가 충분히 들어 있다.
다만 논문은 19개 윈도우를 최종 시행 예측으로 결합하는 정확한 방법을
명시하지 않았기 때문에 위 시행별 결과가 논문을 완전히 재현한 결과라고
단정할 수는 없다.

논문의 데이터 단위:
- 전체 시행: 1,920개
- 학습 시행: 1,536개
- 테스트 시행: 384개
- 시행당 윈도우: 19개

현재 dataset.npz의 데이터 단위:
- 학습 행: 29,184개 = 1,536 × 19
- 테스트 행: 7,296개 = 384 × 19


======================================================================
2. 데이터 전처리의 문제
======================================================================

2.1 논문과 일치하는 부분

- 60 Hz 노치 필터
- 20~450 Hz 4차 Butterworth 대역통과 필터
- filtfilt를 이용한 영위상 필터링
- RMS, MAV, WL, ZC, SSC 특징
- ZC 임계값 0.01
- 200 ms 윈도우와 100 ms hop

따라서 필터 또는 특징 수식만으로 정확도가 약 30%p 이상 낮아졌다고
보기는 어렵다.

2.2 논문에 없는 onset 정렬

현재 파이프라인은 각 시행의 onset을 검출해 2초 위치로 이동한 뒤
특징을 추출한다. 이 절차는 논문에 명시된 전처리가 아니라 프로젝트에서
추가한 처리다. 따라서 논문과 현재 모델의 입력 신호가 완전히 같지 않다.

1,920개 시행의 전처리 보고서를 확인한 결과:
- onset 100 ms 미만 QC 시행: 54개
- onset 이동량 중앙값: 986샘플
- onset 이동량 범위: -872~2,000샘플
- 보완 구간이 분석 시작점 1,500샘플을 침범한 시행: 173개

프로토콜상 동작 전 휴식 구간이 있는데도 onset이 0~100 ms에 검출된
시행은 오검출 가능성이 있다. 이러한 시행도 현재 자동 정렬과 특징
추출에 포함된다.

2.3 결측 보완값의 데이터 누수 가능성

시간축 정렬은 학습·테스트 분할 전에 파일 전체 30회 시행을 이용해
수행된다. 이후 dataset_maker.py에서 시행을 학습·테스트로 분할한다.

따라서 테스트 시행의 원본 값이 학습 시행의 결측 보완에 사용될 수 있다.
이는 정확도를 낮추는 원인이라기보다 평가 정확도를 부당하게 높일 수 있는
데이터 누수 문제다.

2.4 분석 구간 시작점 불확실성

현재 코드는 정렬된 시행의 1.5초부터 2초 구간, 즉 1.5~3.5초를 사용한다.
강의자료는 1.5초 시작점을 실습 가정이라고 명시하며, 논문은 2초
세그먼트의 정확한 시작점을 명시하지 않는다.

현재 onset은 2초에 배치되므로 분석 구간에 동작 전 휴식, 동작 구간,
동작 후 구간이 함께 포함된다. 윈도우별 RF 정확도도 위치에 따라
40.6~74.2%로 크게 달랐다. onset 경계와 마지막 휴식 쪽 윈도우의
정확도가 특히 낮았다.

2.5 해결 방안

- 논문 재현 실험과 onset 정렬 추가 실험을 분리한다.
- 우선 원본 시행에 논문 필터만 적용한 기준 데이터셋을 만든다.
- 시작점이 확인되지 않으면 1.0, 1.5, 2.0초 등의 민감도 실험을 한다.
- onset 정렬을 유지하면 100 ms 미만 QC 시행을 수동 검토하거나 제외한다.
- 결측 보완은 분할 후 학습 시행 donor만 사용한다.
- 입력의 bandpass 열이 장비에서 이미 필터링된 신호인지 확인한다.


======================================================================
3. 전처리 데이터를 데이터셋으로 만드는 과정의 문제
======================================================================

3.1 핵심 문제: 윈도우를 독립 표본으로 저장

dataset_maker.py는 시행 하나에서 생성된 19개 윈도우를 각각 하나의
학습 표본으로 저장한다. 일부 200 ms 윈도우에는 동작 정보가 거의 없지만
모든 윈도우에 해당 시행의 전체 동작 라벨이 부여된다.

이 때문에 현재 정확도는 시행 분류 정확도가 아니라 윈도우 분류
정확도가 된다. 논문의 384개 테스트 시행 정확도와 직접 비교할 수 없다.

3.2 시행 메타데이터가 저장되지 않음

현재 dataset.npz에는 다음 정보가 없다.
- trial_id
- subject_id
- window_index
- 동일 시행에 속한 윈도우의 그룹 정보
- QC 및 onset 이동 정보

현재는 행 순서가 19개씩 유지된다는 사실에 의존해야 한다. 데이터 순서가
바뀌면 어떤 윈도우가 같은 시행에 속했는지 복원하기 어렵다.

3.3 권장 데이터 구조

Xtr: (1536, 19, 25)
ytr: (1536,)
Xte: (384, 19, 25)
yte: (384,)
subject_id
trial_id
window_index
qc_flags

3.4 모델 입력 구성 방법

방법 A: 윈도우 모델과 시행별 결합
- 각 윈도우를 모델로 예측한다.
- 같은 시행의 19개 예측을 다수결 또는 확률 평균으로 결합한다.
- 최종 정확도는 384개 시행을 기준으로 계산한다.

방법 B: 시행 단위 특징 생성
- 19개 윈도우 특징을 평균·표준편차 등으로 요약한다.
- 또는 윈도우 순서를 유지해 하나의 시행 특징으로 결합한다.
- 시행마다 하나의 예측을 만든다.
- 논문에 상세 방식이 없으므로 사용한 방법을 재현 가정으로 기록한다.

진단 목적으로 19개 윈도우의 특징을 순서대로 연결한 475차원 시행
특징을 사용했을 때의 hold-out 정확도:
- SVM: 94.53%
- RF: 94.53%
- XGB: 91.93%

이는 현재 데이터에 분류 정보가 부족한 것이 아니라 입력 구성과 평가
단위가 성능에 큰 영향을 준다는 증거다. 단, 475차원 연결은 논문에서
확인된 방식은 아니다.

3.5 분할과 표준화

- 현재 시행을 먼저 분할한 것은 윈도우 누수 방지 측면에서 올바르다.
- 클래스 분포도 균등하다.
- StandardScaler를 학습 데이터에 fit하고 테스트 데이터에는 transform만
  적용한 것도 올바르다.
- 교차검증에서도 같은 시행의 19개 윈도우가 서로 다른 폴드에 들어가지
  않도록 trial_id를 그룹으로 사용해야 한다.


======================================================================
4. 머신러닝 코드 자체의 문제
======================================================================

4.1 정확도 계산 단위

현재 machine_learning.py는 다음 순서로 평가한다.

1) 7,296개 윈도우를 예측한다.
2) 각 윈도우의 라벨과 예측을 accuracy_score로 비교한다.

시행별 결합이 없으므로 출력되는 정확도는 윈도우별 정확도다.

4.2 모델 파라미터

SVM과 Random Forest 설정은 논문 자료와 거의 같다. XGBoost에는 다음
파라미터를 명시적으로 추가하는 것이 좋다.

objective='multi:softprob'
reg_lambda=1.0
tree_method='hist'

그러나 이 파라미터의 누락이 현재 정확도가 48~62%가 된 주원인은 아니다.

4.3 시행별 예측 결합

- Random Forest와 XGBoost는 predict_proba 결과를 시행별로 평균한 뒤
  argmax를 적용할 수 있다.
- SVM은 19개 예측의 다수결 또는 decision_function 평균을 사용할 수 있다.
- SVM에서 확률 평균이 필요하면 probability=True를 사용할 수 있지만
  학습 시간이 증가한다.
- SVM은 윈도우별 학습보다 시행 단위 특징을 사용할 때 성능이 크게
  개선될 가능성이 있다.

4.4 논문과 같은 검증 조건

- hold-out 최종 테스트 표본 수가 384개인지 확인한다.
- 클래스당 테스트 시행 수가 48개인지 확인한다.
- 혼동행렬 전체 합이 384인지 확인한다.
- 5-fold에서도 시행 그룹을 유지한다.
- 정확도뿐 아니라 macro precision, recall, F1을 계산한다.
- 하이퍼파라미터 튜닝은 평가 단위를 수정한 뒤 학습 폴드 안에서만 한다.


======================================================================
5. 권장 재구성 순서
======================================================================

1) 논문 재현용 전처리와 추가 onset 정렬 전처리를 분리한다.

2) 각 시행의 subject_id, trial_id, label, QC 정보를 먼저 만든다.

3) 시행 단위로 학습·테스트를 8:2 층화 분할한다.

4) 학습 시행과 테스트 시행에서 각각 필터, 세그먼트, 윈도우, 특징을
   생성한다. 결측 보완이 필요하면 학습 데이터 donor만 사용한다.

5) 데이터셋을 (시행 수, 19, 25) 형태로 저장하고 메타데이터도 함께
   저장한다.

6) StandardScaler는 학습 데이터에서만 fit한다. 윈도우 특징을 사용할지
   시행 특징을 사용할지에 따라 스케일링 단위를 명확히 정한다.

7) 먼저 윈도우 모델을 학습한 뒤 시행별 다수결과 점수·확률 평균을
   비교한다.

8) 필요하면 평균·표준편차 요약 또는 순서 보존 결합 방식도 비교한다.

9) hold-out 테스트는 384개 시행 기준으로 계산한다.

10) 5-fold 교차검증에서도 trial_id 그룹을 유지한다.

11) onset 정렬 유무, 세그먼트 시작점, QC 시행 포함 여부를 각각 하나씩
    바꾸는 ablation 실험을 수행한다.

12) 데이터와 평가 단위가 확정된 뒤에만 SVM C/gamma와 트리 모델
    하이퍼파라미터를 조정한다.


======================================================================
6. 현재 판단
======================================================================

영향도가 매우 큰 문제:
- 윈도우 정확도를 논문의 시행 정확도와 비교한 것
- 시행별 19개 윈도우 결합 과정이 없는 것

영향도가 큰 문제:
- 논문에서 명시하지 않은 onset 정렬 추가
- 논문에서 명시하지 않은 2초 구간 시작점 사용
- SVM에 적합하지 않은 윈도우 독립 학습 및 평가

평가 신뢰성에 영향을 주는 문제:
- 분할 전 전체 시행을 사용한 결측 보완
- 조기 onset QC 시행을 그대로 정렬한 것
- trial_id, subject_id, window_index를 저장하지 않은 것

주원인이 아닌 것으로 판단되는 부분:
- 클래스 불균형: 현재 8개 클래스는 균등함
- LabelEncoder 사용
- 학습 데이터 기준 StandardScaler 적용
- SVM 및 RF의 기본 하이퍼파라미터


======================================================================
7. 남은 확인 사항
======================================================================

- 논문의 2초 세그먼트 정확한 시작점
- 19개 윈도우를 최종 시행 예측으로 결합한 원 논문의 방식
- 입력 bandpass 열에 이미 적용된 장비 필터의 사양
- 원 논문에서 사용한 정확한 hold-out 무작위 분할
- onset 정렬을 제거했을 때의 시행별 성능

이 정보가 없으면 논문과 완전히 동일한 수치 재현은 보장하기 어렵다.
새 데이터셋 결과를 해석할 때는 윈도우 정확도와 시행 정확도를 반드시
구분해 기록해야 한다.
